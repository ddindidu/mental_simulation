# `evaluate_turns` → `evaluate_turns_strict` 변경 배경

## 1. 기존 방식의 문제

**기존 `evaluate_turns`**:
- n번째 턴의 환자 답변만 분석해서 증상을 식별
- 그 증상으로 매칭되는 질환들을 TP로 간주

**문제점**:
- 의사 LLM은 n번째 턴뿐만 아니라 **1~n턴 전체 대화 맥락**을 보고 후보 질환을 내놓음
- 하지만 평가 쪽은 n번째 턴의 단일 응답만 보고 TP를 판정
- 두 기준의 비대칭으로 인해, 턴이 진행될수록 의사는 누적 정보로 후보를 좁히는 반면 TP는 여전히 좁은 기준으로만 잡혀 **precision이 급락**

## 2. 첫 보정 시도: 증상 누적

- TP 판정을 **n번째 턴의 증상이 아닌, 1~n턴에 걸쳐 누적된 증상**으로 가능한 질환까지 확장

**새로 생긴 문제**:
- 증상이 누적될수록 그 증상으로 매칭되는 질환이 기하급수적으로 늘어남
- → 너무 많은 질환이 TP로 간주되어 평가의 변별력이 떨어짐

## 3. 최종 해결: +증상과 −증상 모두 추적

환자 답변에서 **확인한 증상(+증상)**뿐만 아니라 **명시적으로 부정한 증상(−증상)**도 함께 추출.

**예시**:
> "아니요, 악몽이나 환각은 없고 그냥 어지러워요."
- **+증상**: 어지러움
- **−증상**: 악몽, 환각

## 4. Method B 판정 로직

1~n턴의 **누적 +증상**으로 가능한 질환 집합을 만든 뒤, **누적 −증상이 필수로 요구되는 질환은 TP 집합에서 제거**.

```
가능한 질환 집합 = { D : +증상이 D의 symptom_pool과 겹침 }
TP 후보      = 가능한 질환 집합 − { D : D의 must_include 그룹이 −증상으로 달성 불가 }
```

## 결과

- 의사의 판단 근거(1~n턴 맥락)와 평가 기준이 **동일한 정보 범위**를 보게 됨
- 누적 확장으로 인한 TP 과잉은 **−증상 기반 배제**로 억제
- 턴이 진행될수록 의사의 감별 능력을 **공정하게** 평가할 수 있음 → precision이 턴 증가에 따라 상승하는 패턴 확보
